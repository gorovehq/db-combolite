1. CMBQL Architecture & Core Fundamentals

1.1 Dual-Paradigm Architecture (SQL & Pipeline Flux)

ComboLite Query Language (CMBQL) is db-combolite's unified query language designed from the ground up for multi-model data access. Unlike traditional relational database query languages where non-relational features (such as vectors, documents, and time series) are grafted on via awkward function extensions, CMBQL treats relational tables, hierarchical JSON documents, HNSW vector embeddings, temporal metric series, and directed graph links as first-class primitives.

To accommodate diverse engineering workflows—from standard relational reporting and business intelligence to real-time IoT signal streaming and high-dimensional AI retrieval-augmented generation (RAG)—CMBQL provides two completely interchangeable, first-class syntax paradigms that compile to the identical underlying binary execution plan:

  • Declarative SQL Paradigm: Standard relational clause structure (SELECT ... FROM ... WHERE ... GROUP BY ... ORDER BY ... LIMIT ...) optimized for complex multi-store joins, schema projections, and traditional analytical reporting.
  • Functional Pipeline Paradigm (Flux / InfluxDB Style): Unidirectional dataflow syntax utilizing pipe operators (| and |>) to chain streaming transformations (Scan(...) | filter(...) | window(...) | aggregate(...) | sort(...) | limit(...)). This style provides intuitive readability for streaming time-series analysis, signal processing, and iterative data refinement.
Zero Semantic Divergence

Both the Declarative SQL parser and the Functional Pipeline parser target the exact same intermediate representation: the CMBQ Structured Operator Tree (Spec 11.10, 14.19). A query written in SQL syntax produces the identical binary opcode stream as the equivalent pipeline expression. Developers and agents are free to select whichever syntax paradigm best communicates the intent of the workflow.

1.2 Volcano Operator Tree Compilation & Zero-Copy Execution

CMBQL execution is governed by a pure Volcano iterator model. The compiler translates human-readable query scripts into a binary tree of operator nodes (tagged with single-byte wire identifiers CDB_QUERY_NODE_*). At runtime, each node provides an iterator interface with three lifecycle methods:

  • open(ctx): Allocates scratch memory arenas and initializes internal state cursors.
  • next(ctx, out_tuple): Pulls a single record from upstream inputs, evaluates expression predicates in place, and yields the transformed tuple without intermediate heap buffering.
  • close(ctx): Cleans up transient state and releases memory budget reservations.

Streaming Pipelines Pipelined

Operators such as Filter, Project, and Unnest operate in true streaming mode. They consume one tuple from their upstream input, apply transformations in-place, and immediately yield the result to downstream sinks with $O(1)$ memory overhead.

Pipeline Breakers Buffered

Operators like Sort, Aggregate, and HybridRank must accumulate input streams before emitting output. CMBQL enforces strict memory budgets (defaulting to 64 KB on microcontrollers and 16 MB on servers), spilling to temporary disk scratch pages when budgets are exceeded.

Opaque Cursor Resumption Stateless

Result sets are never materialized in memory in their entirety. Instead, the engine hands back an opaque binary continuation token that captures the physical page and slot offsets, enabling stateless cursor resumption across client batch requests.

1.3 Automated 4-Tier Dotted Path Resolution

In heterogeneous multi-model environments, the period (.) character carries multiple conflicting meanings:

  1. A literal character within a telemetry metric name or MIME key (e.g. cpu.idle.percentage, content.type).
  2. A qualifier separating a table or stream alias from a column name (e.g. users.email).
  3. A structural path delimiter traversing nested JSON document hierarchies (e.g. profile.billing.address.zipcode).

Rather than requiring complex escaping or non-standard syntax, CMBQL implements an automated 4-Tier Path Resolution Engine (Spec 11.11.2):

Tier Resolution Rule Syntax Pattern Compiled Binary Representation Behavioral Description
Tier 1 Explicit Quoting "cpu.idle"
'cpu.idle'
`cpu.idle`
Field("cpu.idle") 		Literal UTF-8 string: cpu.idle Enclosing an identifier in quotes or wrapping it in the Field() pseudo-constructor explicitly disables path splitting. The dot is preserved as an exact literal byte.
Tier 2 Schema Auto-Matching cpu.idle (unquoted) Catalog column ID or exact name: cpu.idle When compiling against a registered store schema (e.g., in a time-series or relational table), unquoted identifiers that match registered column names containing literal dots resolve as a single literal field name without splitting.
Tier 3 Source Stream Qualification telemetry.voltage Source: telemetry, Column: voltage If the first segment of an unquoted dotted path matches an active store name, scan source, or subquery alias in the query's lexical scope, the prefix is stripped as a source qualifier, and the remainder is resolved against that source's schema.
Tier 4 Schemaless Document Fallback user.address.city Unit Separator delimited: user\x1Faddress\x1Fcity In schemaless document stores or untyped pools, any dotted identifier not matched by Tiers 2 or 3 is treated as a nested document path. The CMBQL compiler replaces literal dots with the ASCII Unit Separator byte (0x1F), allowing zero-copy in-page document path traversal.

1.4 Literals, Data Types & Operator Precedence

CMBQL supports a rich set of literal tokens and expression operators:

Literal Representations

  • Integers: Decimal (42, -100) or Hexadecimal (0x2A, 0xFF00).
  • Floats: Standard (3.14159) or Scientific (1.25e-4).
  • Strings: Single quotes ('hello'), double quotes ("world"), backticks (`path`). Supports standard backslash escape sequences (\n, \t, \xHH).
  • Booleans: TRUE, FALSE (case-insensitive).
  • Null: NULL (represents unknown, absent, or uninitialized values).
  • Arrays: Bracketed elements [1, 2, 3], vector literals [0.12, -0.45, 0.88].
  • Document Literals: JSON objects {"name": "Alice", "role": "admin"}.

Operator Precedence (High to Low)

  1. (), [] (Grouping and member indexing)
  2. Unary: +, -, ~, NOT, !
  3. Multiplicative: *, /, %
  4. Additive: +, -
  5. Bitwise Shift: <<, >>
  6. Comparison: ==, !=, <, <=, >, >=, LIKE, ILIKE, IN
  7. Null Check: IS NULL, IS NOT NULL
  8. Conjunction: AND, &&
  9. Disjunction: OR, ||

2. Declarative SQL Language Reference

CMBQL Declarative SQL provides a familiar relational querying syntax extended to support multi-model data sources, graph traversal, and high-dimensional vector search. A declarative query is structured into explicit clauses evaluated according to the standard relational algebra lifecycle.

2.1 SELECT Clause & Projection Expressions

The SELECT clause defines the output schema emitted by the query. In the compiled operator tree, this maps directly to a Project node (CDB_QUERY_NODE_PROJECT).

Form Syntax Example Behavior & Execution Semantics
Wildcard (*) SELECT * FROM users; Emits all columns or fields produced by the upstream source. Sets passthrough = 1 in the binary projection node.
Explicit Fields SELECT user_id, email FROM users; Extracts only the specified field names, projecting away all unlisted fields.
Expressions & Aliases SELECT id, price * 1.08 AS gross_price FROM orders; Evaluates scalar expressions per row and assigns an output alias using either AS alias or : alias syntax.
Nested Field Projection SELECT id, profile.billing.city AS city FROM accounts; Applies 4-Tier path resolution to extract nested JSON document attributes into flat output columns.
Function Expressions SELECT sin(radians(angle)) AS s, length(name) AS len FROM points; Calls built-in scalar, math, spatial, or string functions directly within the projection pipeline.

2.2 FROM Clause & Stream Operator Constructors

Unlike conventional databases where the FROM clause can only reference named tables or views, CMBQL allows FROM to instantiate any Stream Operator Constructor. This allows full-text searches, vector distance lookups, time-series windows, and graph traversals to act as first-class tuple sources.

Supported Source Constructors:

  • Table / Store Identifier: FROM accounts or FROM "raw-events" (automatically wraps as Scan("store")).
  • Explicit Table Scan: FROM Scan("telemetry", start_key: "sensor_001", end_key: "sensor_100").
  • Full-Text Search Source: FROM TextSearch("articles", fields: ["content"], query: "distributed consensus").
  • Vector Similarity Source: FROM VectorSearch("embeddings", Field("$vector"), near: [0.12, -0.45, 0.88], k: 20).
  • Hybrid Search Source: Combines keyword relevance and vector similarity via Reciprocal Rank Fusion (RRF): 
    FROM HybridRank(
    TextSearch("docs", fields: ["body"], query: "fault tolerance"),
    VectorSearch("docs_vec", Field("$vector"), near: $query_vec, k: 50),
    weights: [0.4, 0.6]
)
  • Graph Traversal Source: Walks outbound or inbound relationships starting from specific nodes: 
    FROM Traverse("social_graph", from: [10, 100], type: "friend_of", direction: "out", hops: 2)
  • Temporal Window Source: Chunks high-frequency events into time buckets: 
    FROM Window("server_metrics", field: "ts", size: 60000000000, step: 60000000000)
  • Subquery / Derived Table: Any parenthesized query expression (including pipeline streams): FROM (SELECT * FROM orders WHERE total > 1000) AS big_orders.

2.3 JOIN & ASOF JOIN Clauses

CMBQL supports cross-model joins across heterogeneous storage formats. An application can join a relational table directly to a schemaless document pool or vector collection in a single atomic query.

Join Type Syntax Pattern Execution Behavior
INNER JOIN FROM a [INNER] JOIN b ON a.id == b.a_id Matches rows from a and b where the ON predicate evaluates to true. Unmatched rows are discarded.
LEFT OUTER JOIN FROM a LEFT [OUTER] JOIN b ON a.id == b.a_id Preserves all rows from the left stream a. If no match exists in b, all fields of b evaluate to NULL (consistent with document absence semantics).
ASOF JOIN FROM trades ASOF JOIN quotes ON trades.symbol == quotes.symbol TIME trades.ts >= quotes.ts [TOLERANCE 100000000] Specialized temporal join for financial and IoT time-series. For each row in trades, matches the single most recent row in quotes having an equal partition key (symbol) where quotes.ts <= trades.ts within an optional tolerance window.

Cross-Model Join Example:

SELECT 
    u.id AS user_id, 
    u.username, 
    p.address.city AS city, 
    v.similarity_score
FROM users AS u
JOIN Scan("profiles") AS p ON u.id == p.user_id
JOIN VectorSearch("user_embeddings", Field("$vector"), near: $target_vec, k: 10) AS v 
  ON u.id == v.user_id
WHERE u.status == "active" AND p.age >= 21;

2.4 WHERE & FILTER Filtering

The WHERE (or synonym FILTER) clause compiles to a Filter node (CDB_QUERY_NODE_FILTER). It evaluates a boolean expression for each incoming tuple.

  • Tri-State Boolean Logic: If an expression references a document field that does not exist in a given record, the field evaluates to NULL. Comparisons against NULL yield NULL (which is treated as falsey by the filter node, safely excluding non-matching documents).
  • Sargable Predicate Pushdown: Equality and range comparisons on primary keys or secondary index columns (e.g. WHERE id == 500 or WHERE created_at BETWEEN 1000 AND 2000) are pushed down directly into the underlying B-Tree index scan, bypassing full-table scans.
  • Null Checking: Explicitly test nullness using IS NULL or IS NOT NULL.

2.5 GROUP BY, ORDER BY, and LIMIT Clauses

Grouping & Aggregates (GROUP BY / AGGREGATE BY)

Groups records by one or more expressions and applies aggregate functions (count, sum, avg, min, max, stddev, variance): 

SELECT 
    device_id, 
    count(*) AS sample_count, 
    avg(temp) AS mean_temp, 
    stddev(temp) AS sigma_temp
FROM Scan("sensor_readings")
WHERE ts >= 1672531199000000000
GROUP BY device_id
HAVING mean_temp > 85.0;

Sorting (ORDER BY / SORT BY)

Sorts records by one or more keys. Each key supports sort direction (ASC or DESC, default ASC) and explicit null placement (NULLS FIRST or NULLS LAST, default NULLS LAST): 

ORDER BY priority DESC NULLS LAST, created_at ASC;

Pagination (LIMIT & OFFSET)

Controls result slice bounds. LIMIT count OFFSET offset skips offset tuples and yields up to count records: 

LIMIT 25 OFFSET 50;  -- Skips 50 rows, returns records 51 through 75

3. Functional Pipeline Syntax (| and |>) & Stream Operators

3.1 Pipeline & Pipe-Forward Overview

The Functional Pipeline syntax in CMBQL provides a linear, left-to-right dataflow model inspired by Unix pipelines, InfluxDB Flux, and Kusto Query Language. Instead of nesting clauses inside deeply indented SQL statements, stages are linked using the pipe operator (| or its synonym |>): 

-- Canonical Pipeline Query
Scan("telemetry")
  | filter(voltage > 3.3 AND status == "active")
  | window(field: "ts", size: 60000000000, step: 10000000000)
  | aggregate(by: [device_id], avg_v: avg(voltage), max_v: max(voltage))
  | sort(avg_v DESC)
  | limit(50);

Each pipe stage consumes an incoming tuple stream from its left-hand input and forwards transformed records to the next stage. Pipeline queries compile into the identical Volcano operator tree as declarative SQL queries.

4. Piping Inside SQL-Like Queries & Hybrid Stream Composition

One of CMBQL's most powerful architectural capabilities is the seamless intermixing of Declarative SQL clauses and Functional Pipeline operators. You are never forced to choose between purely relational SQL and purely functional pipelines: pipe operators (| and |>) can be used within SQL FROM clauses, subqueries, Common Table Expressions (CTEs), and even directly attached to the tail of a SELECT statement.

4.1 Piping Inside the FROM Clause (Derived Pipelines)

Any parenthesized pipeline expression can serve as a derived source table within a SQL FROM or JOIN clause. The pipeline stream is compiled into an inline Volcano sub-tree, providing zero-overhead, memory-bounded sub-query processing: 

-- Pipeline used as a derived source inside SQL
SELECT 
    hot_sensors.device_id, 
    hot_sensors.temp, 
    d.location, 
    d.technician_contact
FROM (
    Scan("telemetry")
      | filter(temp >= 95.0 AND status == "active")
      | sort(temp DESC)
      | limit(100)
) AS hot_sensors
JOIN devices AS d ON hot_sensors.device_id == d.id
WHERE d.facility == "Building-4";
Why Use Pipes Inside FROM?

Piping inside FROM allows developers to write clean, linear preprocessing pipelines (such as metric filtering, windowing, or vector retrieval) before joining the resulting compact candidate set against large relational tables or document collections.

7. Stored Procedures & Procedural Logic (CMBP Bytecode)

db-combolite stored procedures are written in CMBQL extended with procedural statements: variables (LET), conditionals (IF / ELSEIF / ELSE), loops (WHILE, FOR), and transaction boundaries. Procedures compile to a sandboxed 64-register bytecode format (CMBP, Spec 11.2, 14.20) stored directly in the system catalog.

7.1 Procedural VM Architecture

  • 64-Register File: Register R0 is the null register; R1..R15 hold incoming procedure arguments; R16..R63 are allocated for variables and temporary expression evaluations.
  • Instruction Budget: Every procedure invocation runs with a configurable instruction budget (e.g. 100,000 opcodes) to guarantee that runaway loops cannot exhaust CPU resources.
  • Zero File/Network Access: Procedures are hermetically sandboxed. They can only interact with database state via engine mutation opcodes (CALL_MUTATION) and query cursors.

7.2 Control Flow Statements

Variable Assignment (LET)

Binds a literal, expression, or subquery stream to a named local variable:

LET $min_balance = 50.0;
LET $active_user = (SELECT * FROM users WHERE id == $user_id);

Conditionals (IF ... THEN ... ELSEIF ... ELSE ... END IF)

Executes conditional branches based on truthy expression values:

IF $user_status == "suspended" THEN
    RETURN -1;
ELSEIF $account_balance < $withdrawal THEN
    RETURN -2;
ELSE
    UPDATE TABLE accounts SET balance = balance - $withdrawal WHERE id == $account_id;
END IF;

Loops (WHILE and FOR)

Iterates over boolean conditions or query result streams:

WHILE $retry_count < 3 DO
    -- procedural body
    LET $retry_count = $retry_count + 1;
END WHILE;

FOR $item IN (Scan("stale_tokens") | filter(expired == TRUE)) DO
    DELETE FROM "stale_tokens" WHERE id == $item.id;
END FOR;

7.3 Savepoints & Error Trapping

When a mutation opcode (CALL_MUTATION) runs within a procedure, it writes its integer cdb_status return code into a destination register. Stored procedures can trap errors, perform partial rollbacks to savepoints, and continue batch operations without failing the overarching transaction: 

-- Complete Procedural Example with Error Trapping
PROCEDURE transfer_funds($src_id, $dst_id, $amount)
BEGIN
    BEGIN TRANSACTION;
    
    LET $src_bal = (SELECT balance FROM accounts WHERE id == $src_id);
    IF $src_bal < $amount THEN
        ROLLBACK;
        RETURN -1;  -- Insufficient funds
    END IF;

    SAVEPOINT before_credit;
    UPDATE TABLE accounts SET balance = balance - $amount WHERE id == $src_id;
    UPDATE TABLE accounts SET balance = balance + $amount WHERE id == $dst_id;
    
    -- Verify destination update
    LET $status = (SELECT count(*) FROM accounts WHERE id == $dst_id);
    IF $status == 0 THEN
        ROLLBACK TO before_credit;
        ROLLBACK;
        RETURN -2;  -- Destination account not found
    END IF;

    COMMIT;
    RETURN 0;       -- Success
END;

Signature: fluid_reynolds(rho, velocity, char_length, dynamic_viscosity)

Computes the dimensionless Reynolds number: $Re = \frac{\rho v L}{\mu}$, characterizing laminar vs. turbulent flow regimes.

Parameters:
PosArgumentTypeReq?Description
1rhoFloatYesFluid density in $\text{kg/m}^3$.
2velocityFloatYesFlow velocity in $\text{m/s}$.
3char_lengthFloatYesCharacteristic geometric length (pipe diameter, chord) in meters.
4dynamic_viscosityFloatYesFluid dynamic viscosity in $\text{Pa}\cdot\text{s}$ (or $\text{kg/(m}\cdot\text{s)}$).

Practical Use Case: Aerodynamic wing analysis, pipeline pumping flow regime classification.

Declarative SQL Usage 
SELECT pipe_id, fluid_reynolds(1000.0, flow_velocity, pipe_dia, 0.001) AS reynolds_no FROM water_pipes;
Pipeline / Flux Usage 
Scan("water_pipes") | select(pipe_id, fluid_reynolds(1000.0, flow_velocity, pipe_dia, 0.001) AS reynolds_no);

9. Formal Grammar & Lexicon (EBNF)

The complete ISO/IEC 14977 Extended Backus-Naur Form (EBNF) grammar specification defining CMBQL tokens, declarations, declarative SQL clauses, pipeline stages, stored procedures, and expression precedence: 

(* ======================================================== *)
(* Lexical Tokens                                           *)
(* ======================================================== *)
Whitespace      ::= [ \t\r\n]+ ;
Comment         ::= '--' [^\n]* | '/*' ( [^*] | '*'+ [^*/] )* '*'+ '/' ;
Letter          ::= [a-zA-Z_] ;
Digit           ::= [0-9] ;
HexDigit        ::= [0-9a-fA-F] ;

Ident           ::= Letter ( Letter | Digit )* ;
Param           ::= '$' ( Letter | Digit )+ ;
IntLit          ::= [0-9]+ | '0x' HexDigit+ ;
FloatLit        ::= [0-9]+ '.' [0-9]+ ( [eE] [+-]? [0-9]+ )? ;
StringLit       ::= '"' ( [^"\\] | '\\' . )* '"'
                  | "'" ( [^'\\] | '\\' . )* "'"
                  | '`' ( [^`\\] | '\\' . )* '`' ;

(* ======================================================== *)
(* Top-Level Declarations                                   *)
(* ======================================================== *)
Program         ::= ( QueryDef | ProcDef | Stmt )* ;

QueryDef        ::= 'QUERY' Ident '(' ParamList? ')' QueryBody ';' ;
ProcDef         ::= 'PROCEDURE' Ident '(' ParamList? ')' 'BEGIN' StmtList 'END' ';' ;
ParamList       ::= ParamDef ( ',' ParamDef )* ;
ParamDef        ::= Param Ident? ;

QueryBody       ::= SelectQuery | PipeQuery ;

(* ======================================================== *)
(* Declarative SQL-Style Syntax                             *)
(* ======================================================== *)
SelectQuery     ::= 'SELECT' SelectList
                    'FROM' FromSource
                    ( JoinClause )*
                    ( WhereClause )?
                    ( GroupByClause )?
                    ( SortByClause )?
                    ( LimitClause )? ;

SelectList      ::= '*' | SelectItem ( ',' SelectItem )* ;
SelectItem      ::= Expr ( ( 'AS' | ':' ) Ident )? ;

FromSource      ::= StreamOp | Ident ( 'AS' Ident )? | '(' QueryBody ')' ;
JoinClause      ::= ( 'INNER' | 'LEFT' 'OUTER'? )? 'JOIN' FromSource 'ON' Expr
                  | 'ASOF' 'JOIN' FromSource 'ON' Ident 'TIME' Ident ( 'TOLERANCE' IntLit )? ;
WhereClause     ::= ( 'WHERE' | 'FILTER' ) Expr ;
GroupByClause   ::= ( 'GROUP' 'BY' | 'AGGREGATE' 'BY' ) GroupList ( 'HAVING' Expr )? ;
GroupList       ::= Expr ( ',' Expr )* ;
SortByClause    ::= ( 'ORDER' 'BY' | 'SORT' 'BY' ) SortList ;
SortList        ::= SortItem ( ',' SortItem )* ;
SortItem        ::= Expr ( 'ASC' | 'DESC' )? ( 'NULLS' ( 'FIRST' | 'LAST' ) )? ;
LimitClause     ::= 'LIMIT' IntLit ( ( 'OFFSET' | ',' ) IntLit )? ;

(* ======================================================== *)
(* Functional Pipeline Syntax                              *)
(* ======================================================== *)
PipeQuery       ::= PipeSource ( PipeOp PipeStage )* ;
PipeOp          ::= '|' | '|>' ;
PipeSource      ::= StreamOp | Ident | '(' QueryBody ')' ;
PipeStage       ::= 'filter' '(' Expr ')'
                  | ( 'project' | 'select' ) '(' SelectList ')'
                  | ( 'sort' | 'order' ) '(' SortList ')'
                  | 'limit' '(' IntLit ( ',' IntLit )? ')'
                  | 'window' '(' NamedArgList ')'
                  | 'aggregate' '(' ( 'by' ':' '[' GroupList ']' ',' )? SelectList ')'
                  | 'join' '(' FromSource ',' 'on' ':' Expr ( ',' 'kind' ':' StringLit )? ')'
                  | 'asof_join' '(' FromSource ',' NamedArgList ')'
                  | 'text_search' '(' NamedArgList ')'
                  | 'vector_search' '(' NamedArgList ')'
                  | 'traverse' '(' NamedArgList ')'
                  | 'hybrid_rank' '(' NamedArgList ')'
                  | 'unnest' '(' Expr ( 'AS' Ident )? ')'
                  | 'into' '(' StringLit ')'
                  | 'yield' '(' DocLiteral ')' ;

(* ======================================================== *)
(* Stream Operator Constructors                             *)
(* ======================================================== *)
StreamOp        ::= 'Scan' '(' StringLit ')'
                  | 'TextSearch' '(' StreamOp ',' NamedArgList ')'
                  | 'VectorSearch' '(' StreamOp ',' NamedArgList ')'
                  | 'HybridRank' '(' NamedArgList ')'
                  | 'Traverse' '(' StreamOp ',' NamedArgList ')'
                  | 'Window' '(' StreamOp ',' NamedArgList ')'
                  | 'AsofJoin' '(' StreamOp ',' StreamOp ',' NamedArgList ')' ;

NamedArgList    ::= NamedArg ( ',' NamedArg )* ;
NamedArg        ::= Ident ':' Expr ;

(* ======================================================== *)
(* Stored Procedure Statements (CMBP)                       *)
(* ======================================================== *)
StmtList        ::= ( Stmt ';' )* ;
Stmt            ::= LetStmt
                  | IfStmt
                  | WhileStmt
                  | ForStmt
                  | ReturnStmt
                  | CallStmt
                  | SavepointStmt
                  | RollbackStmt
                  | ReleaseStmt
                  | InsertStmt
                  | UpdateStmt
                  | DeleteStmt
                  | PatchStmt
                  | ReplaceStmt
                  | LinkStmt
                  | UnlinkStmt
                  | AppendStmt
                  | BeginTxStmt
                  | CommitTxStmt ;

LetStmt         ::= 'LET' Param '=' ( QueryBody | Expr ) ;
IfStmt          ::= 'IF' Expr 'THEN' StmtList ( 'ELSEIF' Expr 'THEN' StmtList )* ( 'ELSE' StmtList )? 'END' 'IF' ;
WhileStmt       ::= 'WHILE' Expr 'DO' StmtList 'END' 'WHILE' ;
ForStmt         ::= 'FOR' Param 'IN' Expr 'DO' StmtList 'END' 'FOR' ;
ReturnStmt      ::= 'RETURN' Expr? ;
CallStmt        ::= 'CALL' Ident '(' ArgList? ')' ;
SavepointStmt   ::= 'SAVEPOINT' Ident ;
RollbackStmt    ::= 'ROLLBACK' ( 'TO' Ident )? ;
ReleaseStmt     ::= 'RELEASE' 'SAVEPOINT' Ident ;
BeginTxStmt     ::= 'BEGIN' ( 'TRANSACTION' | 'TX' )? ;
CommitTxStmt    ::= 'COMMIT' ( 'TRANSACTION' | 'TX' )? ;

(* Multi-Model Mutations *)
InsertStmt      ::= 'INSERT' 'INTO' ( 'TABLE' Ident '(' IdentList ')' 'VALUES' '(' ArgList ')'
                                    | 'VECTORS' Ident '(' StringLit ')'
                                    | Ident '(' StringLit ( ',' StringLit )? ')' ) ;
UpdateStmt      ::= 'UPDATE' 'TABLE' Ident 'SET' SetList ( 'WHERE' Expr )? ;
DeleteStmt      ::= 'DELETE' 'FROM' ( 'TABLE' | 'VECTORS' )? Ident ( 'WHERE' Expr )? ;
PatchStmt       ::= 'PATCH' Ident Expr 'WITH' StringLit ;
ReplaceStmt     ::= 'REPLACE' Ident Expr 'WITH' StringLit ;
LinkStmt        ::= 'LINK' Expr 'FROM' Expr 'TO' Expr ( 'WEIGHT' FloatLit )? ( 'TIME' IntLit )? ;
UnlinkStmt      ::= 'UNLINK' Expr 'FROM' Expr 'TO' Expr ;
AppendStmt      ::= 'APPEND' 'INTO' 'TIMESERIES' Ident 'SERIES' IntLit 'TIME' IntLit 'VALUE' FloatLit ;

(* ======================================================== *)
(* Expressions & Precedence Hierarchy                      *)
(* ======================================================== *)
Expr            ::= OrExpr ;
OrExpr          ::= AndExpr ( 'OR' AndExpr )* ;
AndExpr         ::= NotExpr ( 'AND' NotExpr )* ;
NotExpr         ::= ( 'NOT' | '!' ) NotExpr | CmpExpr ;
CmpExpr         ::= AddExpr ( ( '==' | '!=' | '<' | '<=' | '>' | '>=' | 'LIKE' | 'ILIKE' | 'IN' | 'IS' 'NULL' | 'IS' 'NOT' 'NULL' ) AddExpr )* ;
AddExpr         ::= MulExpr ( ( '+' | '-' ) MulExpr )* ;
MulExpr         ::= UnaryExpr ( ( '*' | '/' | '%' ) UnaryExpr )* ;
UnaryExpr       ::= ( '+' | '-' | '~' ) UnaryExpr | PrimaryExpr ;

PrimaryExpr     ::= Literal
                  | Param
                  | FieldRef
                  | CallExpr
                  | '(' Expr ')'
                  | ArrayLit
                  | DocLiteral ;

FieldRef        ::= 'Field' '(' StringLit ')'
                  | StringLit
                  | DottedIdent ;

DottedIdent     ::= Ident ( '.' Ident )* ;
CallExpr        ::= Ident '(' ArgList? ')' ;
ArgList         ::= Expr ( ',' Expr )* ;
ArrayLit        ::= '[' ( Expr ( ',' Expr )* )? ']' ;
DocLiteral      ::= '{' ( NamedArg ( ',' NamedArg )* )? '}' ;
Literal         ::= 'TRUE' | 'FALSE' | 'NULL' | IntLit | FloatLit | StringLit ;
